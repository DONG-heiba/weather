# 研究生课程作业

## 题目

### 2026 年 8 月天气预报可视化网页

## 一、作业背景

本作业要求设计并实现一个面向公众使用的天气预报可视化网页。网页应结合数值天气预报数据与在线地图，为用户提供 2026 年 8 月天气变化的空间分布和时间演变信息。最终实现类似Windy.com 的效果是“地图引擎 + 气象格点数据 + Canvas/WebGL 连续渲染 + 粒子动画 + 时间序列控制”共同实现

重点考察内容包括：

- 气象数据的获取、整理与可视化；
- 地图交互与空间信息表达；
- 多种天气图层的切换；
- 单点天气查询；
- 时间轴与天气动画；
- 对气象数据含义的清晰说明。

## 二、时间范围

- 展示时间范围：*为数据实际时间范围
- 时间切换粒度可根据数据实际情况设置为小时、3 小时、6 小时或日期；
- 网页应明确标注当前展示的时间、时区和数据更新时间。

## 三、指定数据源

### 1. 气象数据源

- **ECMWF IFS Open Data**
- **Open-Meteo**

可以根据接口可用性和数据格式选择其中一个或结合使用。网页中应注明数据来源，并在项目说明中简要描述数据的时间分辨率、空间分辨率和主要变量。利用pandas清洗需要的数据

### 2. 地图数据源

- **OpenStreetMap**

地图应支持基础底图展示，并用于定位天气数据的空间位置。

## 四、核心功能要求

### 1. 可缩放、可拖动地图

网页至少应包含一张交互式地图，并满足以下要求：

- 支持鼠标拖动或触摸拖动；
- 支持放大和缩小；
- 支持地图平移后继续查看天气信息；
- 地图应具有基本的地理标注或图例；
- 地图底图来源应标注为 OpenStreetMap。
- 热力图随着鼠标移动地图及时的更新位置

### 2. 天气图层切换

网页至少需要实现以下天气信息中的 **两种**：

- 风场；
- 温度；
- 降雨；
- 云量；
- 气压。

建议实现三种或以上图层，以体现综合可视化能力。

用户应能够通过按钮、菜单、标签页或其他清晰的控件切换天气图层。当前启用的图层应有明显的状态提示。

### 3. 天气信息表达

不同天气变量可以采用以下方式表达：

| 天气变量 | 推荐表达方式 | 应说明的含义 |
| --- | --- | --- |
| 风场 | 粒子动画、箭头、流线、颜色 | 风向、风速及其空间分布 |
| 温度 | 颜色覆盖、热力图、等值线 | 不同地点的气温高低 |
| 降雨 | 颜色覆盖、热力图、等值线、点状符号 | 降雨量或降雨强度 |
| 云量 | 透明度、颜色覆盖、云量图 | 云覆盖程度 |
| 气压 | 等值线、颜色覆盖、标签 | 地面气压及高低压分布 |

网页应提供图例、单位和简短说明，使用户能够大致理解当前地图上展示的数据含义。

### 4. 查看某个位置的天气信息

用户应能够查看地图上某个位置的天气信息，至少支持以下一种方式：

- 点击地图位置；
- 点击天气网格或色带区域；
- 输入经纬度；
- 搜索地点后定位。

单点信息建议包含：

- 地点名称或经纬度；
- 当前时间；
- 温度；
- 风速与风向；
- 降雨量或降雨概率；
- 云量或气压；
- 当前数据图层对应的数值和单位。

### 5. 切换时间

网页应包含时间控制组件，例如：

- 时间滑块；
- 日期选择器；
- 时间下拉菜单；
- 上一时刻和下一时刻按钮。

切换时间后，地图上的天气图层和单点天气信息应同步更新。

### 6. 播放天气变化动画

网页应支持播放天气变化动画，至少包括：

- 播放；
- 暂停；
- 重置；
- 当前时间显示；
- 时间进度指示。

播放动画时，天气图层应随时间变化。动画速度应适合观察，且不能影响用户拖动和缩放地图。

## 五、界面与交互要求

- 页面布局应清晰，地图应作为主要视觉区域；
- 图层切换、时间控制和图例应容易找到；
- 当前图层和当前时间应有明确提示；
- 地图、控件和文字在常见桌面尺寸下不应发生明显遮挡；
- 页面应具有基本的响应式能力，能够适配较小屏幕；
- 加载中、数据加载失败和暂无数据时应提供提示；
- 不同颜色应具有足够对比度；
- 不应只依赖颜色表达信息，必要时应结合数值、图例或符号；
- 页面应注明数据来源、地图来源和版权信息。

## 六、建议的数据处理流程

1. 通过get_data.py获取 Open-Meteo 的 2026 年 8 月部分气象数据；
2. 读取并整理时间、经纬度和气象变量；
3. 将气象数据转换为适合地图展示的格式；
4. 将天气数据与地图坐标进行匹配；
5. 根据当前图层和时间生成颜色、箭头、粒子或等值线；
6. 根据用户操作更新地图和单点信息；
7. 实现时间轴动画；
8. 对异常数据、空数据和接口错误进行处理。

## 十二、项目实现说明

本项目已按上述要求实现为一个前后端分离的天气预报可视化网页。

### 1. 数据处理

- `get_data.py` 使用 Open-Meteo Forecast API 获取区域格点预报数据。
- 当前 `cache.sqlite` 已清洗入库，包含 `weather_hourly`、`locations`、`places`、`metadata` 四张表。
- 主要变量包括 2 米气温、10 米风速、10 米风向、降水概率、小时降水量、总云量、海平面气压，以及由风速风向换算得到的 `u`、`v` 风矢量。
- 当前数据时间分辨率为逐小时，空间格点范围和步长记录在 `metadata` 表中。

### 2. 后端接口

后端入口为 `main.py`，采用 FastAPI 提供以下接口：

- `GET /api/health`：检查服务和 SQLite 数据是否可用。
- `GET /api/meta`：返回时间轴、图层说明、图例范围、参考城市、数据来源与地图来源。
- `GET /api/field`：按当前地图视窗、图层和时间索引返回连续渲染所需的格点场数据。
- `GET /api/point`：按经纬度、时间索引和当前图层返回单点天气详情。

### 3. 前端功能

前端入口为 `src/App.vue`，技术栈为 Vue3 + Vite + Element Plus + Leaflet。

- OpenStreetMap 作为可拖动、可缩放底图。
- Canvas 覆盖层渲染温度、降雨、风场、云量、气压五类图层。
- 风场图层额外提供粒子动画，用于表达风向和风速。
- 时间滑块、上一时刻、下一时刻、播放、暂停、重置和播放速度控制可同步更新地图图层与选点信息。
- 支持地图点击选点和城市搜索定位。
- 右侧面板展示单点温度、风速风向、降雨、云量、气压、坐标、摘要和当前图层数值。
- 底部图例显示当前图层单位、色带、范围、均值、数据来源和地图来源。

### 5. 测试说明

- 地图交互：拖动地图、缩放地图后，天气覆盖层应随视窗重新渲染。
- 图层切换：依次切换温度、降雨、风场、云量、气压，图例和地图颜色应同步变化。
- 单点查询：点击任意位置或选择城市后，右侧天气面板应更新坐标、时间和气象变量。
- 时间切换：拖动时间滑块或点击上一/下一时刻，地图图层与单点天气应同步更新。
- 动画播放：点击播放后时间轴自动推进；暂停、重置和速度切换应生效。
